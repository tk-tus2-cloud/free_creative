# 提案書：部門予算管理のDX推進による「経営の見える化」と組織力強化

**提出先**：経営企画部門・事業部長各位
**提出者**：（所属部署・氏名）
**提出日**：2026年7月

---

## 1. エグゼクティブサマリー

現在、各部門の予算・実績管理は Excel ファイルの個別管理に依存しており、**集計の属人化・数字の鮮度の低さ・部門間比較の困難さ**という3つの経営課題を抱えています。

本提案は、私が現場の課題意識から**既に自主開発・実証済みの「部門予算管理 Web アプリ」**を起点に、全社の予算管理プロセスを段階的に標準化・自動化するものです。

- **定量効果**：月次集計工数を全社で **約120時間/月削減**（試算）、月次報告のリードタイムを **5営業日 → 1営業日** に短縮
- **定性効果**：経営層がリアルタイムに全部門の執行率を把握でき、**期中の予算再配分など打ち手の意思決定が早まる**
- **投資**：初期フェーズは既存プロトタイプを活用するため **追加ライセンス費用ゼロ** で開始可能

小さく始めて確実に成果を出し、効果を検証しながら全社展開する「スモールスタート・クイックウィン」のアプローチで、リスクを最小化しつつ確実にリターンを刈り取ります。

## 2. 現状の課題（As-Is）

| # | 課題 | 具体的な状況 | 経営への影響 |
|---|------|--------------|--------------|
| 1 | 集計の属人化 | 各部門の担当者が独自フォーマットの Excel で管理。担当者不在時に数字が出せない | 業務継続リスク・内部統制上の弱点 |
| 2 | 数字の鮮度 | 月次締め後、各部門からの提出・突合・修正に約5営業日 | 経営判断が常に「1週間前の数字」に基づく |
| 3 | 部門間比較の困難さ | フォーマットが不統一で、費目の粒度もバラバラ | 全社最適の予算再配分ができず、期末の「使い切り」や失効予算が発生 |

現場ヒアリング（自部門および隣接2部門）では、**予算集計・報告資料作成に1部門あたり月8〜10時間**を要していることを確認しました。これは全社（約15部門）に換算すると **月120時間超＝年間約1,700時間** に相当します。

---

## 3. 提案内容（To-Be）：3つの柱

### 柱1：予算管理プロセスの標準化（すぐやる）

- 費目マスタ・入力フォーマットを全社統一し、月次の入力ルール（締め日・責任者）を明文化する
- **既に開発済みの部門予算管理アプリ**を標準ツールとして提供
  - 部門・費目の管理、月次（4月〜3月）の予算・実績入力
  - 予算 / 実績 / 差額 / 執行率のワンクリック切り替え
  - 全部門横断の比較チャート・サマリーダッシュボード
  - CSV 出力による既存の経理システム・報告資料との連携

### 柱2：経営ダッシュボードによる「見える化」（3ヶ月以内）

- 全部門の執行率を経営層がいつでも閲覧できるダッシュボードを整備
- 執行率のしきい値アラート（例：Q2 終了時点で執行率 30% 未満 / 110% 超の部門を自動ハイライト）
- 期中の予算再配分会議を**四半期ごとに定例化**し、データに基づく資源配分を仕組み化

### 柱3：運用体制づくりと人材育成（6ヶ月以内）

- 各部門に「予算管理キーパーソン」を1名任命し、私が主催する**月1回の勉強会**でスキルを底上げ
- 操作マニュアル・FAQ を整備し、属人化を構造的に解消
- 若手メンバー2名を運用チームに巻き込み、**改善提案が現場から継続的に生まれる体制**を作る

## 4. 期待効果

### 定量効果（年間試算）

| 項目 | 現状 | 導入後 | 効果 |
|------|------|--------|------|
| 集計・報告工数 | 約1,700時間/年 | 約400時間/年 | **▲約1,300時間/年**（人件費換算 約400万円相当） |
| 月次報告リードタイム | 5営業日 | 1営業日 | **▲4営業日** |
| 期末失効予算 | 発生（金額は要実測） | 期中再配分で有効活用 | 予算執行の質向上 |

### 定性効果

- **意思決定の高速化**：経営層が「今の数字」で判断できる
- **内部統制の強化**：入力履歴の一元管理により監査対応が容易に
- **組織文化の変革**：現場発の改善が評価される成功事例となり、他業務のDXへの波及効果

## 5. 実行計画（ロードマップ）

```
フェーズ1（〜1ヶ月）   : 自部門＋協力2部門でパイロット運用、効果測定
フェーズ2（2〜3ヶ月）  : フィードバック反映、経営ダッシュボード整備
フェーズ3（4〜6ヶ月）  : 全部門展開、キーパーソン任命・勉強会開始
フェーズ4（7ヶ月〜）   : 定着化、四半期予算再配分会議の定例化、効果報告
```

各フェーズの終了時に**効果測定レポートを経営層へ提出**し、次フェーズへの移行可否を判断いただきます（Go/No-Go 判定）。うまくいかない場合に撤退できる設計にすることで、投資リスクを限定します。

## 6. 体制・リスクと対策

**推進体制（提案）**

- プロジェクトリーダー：提案者（本業務との兼務、工数 20%）
- 運用メンバー：若手2名（育成を兼ねる）
- スポンサー：経営企画部門長（お願いしたい役割：部門間調整の後ろ盾）

**主要リスクと対策**

| リスク | 対策 |
|--------|------|
| 現場の入力負荷への抵抗 | パイロット部門の「工数が減った」実績を先に作り、数字で説得する |
| データの信頼性（localStorage 依存） | フェーズ2で社内サーバー / クラウドへのデータ保存に移行。移行までは CSV バックアップ運用をルール化 |
| 担当者異動による停滞 | マニュアル整備＋キーパーソン複数名体制で属人化を防止 |
| セキュリティ | 社内ネットワーク限定公開とし、情報システム部門のレビューを受ける |

## 8. なぜ私がこの提案を推進するのか

1. **課題を「自分ごと」として動いた実績**：指示を待たず、現場の課題からプロトタイプを自主開発し、動くもので価値を実証しました
2. **現場と経営の両方の視点**：現場の入力負荷を最小化しつつ、経営層が欲しい「執行率の横断比較」を最初から設計に組み込んでいます
3. **人を育てる意志**：本プロジェクトを若手育成の場として設計しており、私がいなくても回る仕組みづくりをゴールとしています

本提案は単なるツール導入ではなく、**「データに基づいて意思決定し、現場から改善が生まれる組織」への第一歩**です。まずはパイロット運用（1ヶ月・追加費用ゼロ）の承認をいただきたく、ご検討のほどよろしくお願いいたします。

## 付録：開発済みプロトタイプの概要

- 技術構成：React 19 + TypeScript + Vite（すべて OSS、ライセンス費用不要）
- 主な機能：部門・費目管理、月次予算実績入力、執行率表示、全部門比較チャート、CSV 出力、年度切替
- 起動方法：`npm install && npm run dev`（本リポジトリ README 参照）
