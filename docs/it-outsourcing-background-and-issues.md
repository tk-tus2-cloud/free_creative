# IT運用・保守アウトソーシング検討 — 背景・課題から目的・ゴールまで（全体ストーリー最終版）

作成日: 2026-08-10
対象: ライオン株式会社 IT運用・保守アウトソーシング検討（Vision2030 2nd Stage「収益力強靭化」文脈）
特徴: 子会社シェアードサービス会社（SSC）へのベンダ統制移管を含む3階層オペレーティングモデル

---

## 全体ストーリー（1枚サマリ）

- 【背景/課題】運用の担い手は先細り（供給↓）、運用業務は増大（需要↑）、ギャップを社員の過負荷で吸収（歪み）、コスト・品質を統制する仕組みも不在（基盤欠如）
- 【So What】現状延長では社員の健康・事業継続・Vision2030の実行力が毀損。内製強化は採用面から成立せず、構造転換以外に選択肢がない
- 【目的】IT運用を「人に依存する固定費・リスク」から「仕組みで統制された変動費・経営基盤」へ転換
- 【目指す姿】本体＝戦略、SSC＝統制、外部ベンダ＝実行の3階層モデル
- 【ゴール】①持続可能な体制 ②コスト構造改革 ③品質の統制 ④社員の戦力シフト

## STEP1: 背景/課題

### 課題1【供給】運用の担い手を維持できない
- 運用・保守の専門人材を採用しておらず、人材獲得競争の激化で今後の採用も現実的でない
- 採用・育成に時間・コストを投じても、運用業務はキャリアとして定着せず投資が回収できない
- シニア社員の経験・暗黙知に依存した属人運用が存在し、異動・退職とともに運用能力が失われる
- So What: 供給は時間とともに確実に細る。「いつ外部化するか」の問題であり「するか否か」の問題ではない

### 課題2【需要】運用業務は増え続ける
- データ基盤・BI・生成AIの活用拡大により、従来と異なる新たな運用業務が増加
- セキュリティ脅威の高度化、EC・グローバル展開により24時間365日対応が標準要求に
- So What: 供給減×需要増でギャップは拡大の一途

### 課題3【歪み】ギャップを社員の過負荷で吸収している
- 定常運用・問い合わせ・障害対応など外部化可能な業務に社員が忙殺され、手戻り・補完などの隠れ工数まで負担
- メンタルヘルス不調者が発生（安全配慮義務に関わる経営リスク）
- 企画業務に時間を投じられず、Vision2030推進の機会損失が発生
- So What: しわ寄せ先は「社員の健康」と「成長投資の時間」

### 課題4【基盤】コスト・品質を統制する仕組みがない
- マルチベンダのブラックボックス化。責任分界・実工数が不明でスケールメリットも不在
- 社員工数・手戻りを含む運用総コスト（TCO）が把握できず、最適化の判断基盤がない
- SLA/KPI未整備で品質を測定できず、復旧は個人の稼働に依存。監査・セキュリティ統制の証跡も担保困難
- So What: 内製・外注いずれを選ぶにせよ、可視化と統制基盤の構築が全ての前提

## STEP2: So What（なぜ構造転換か）

- ギャップは放置すれば拡大の一途、被害はすでに顕在化
- 内製強化（採用・増員）は人材市場の構造上成立しない → 消去法でも外部活用が唯一解
- ただし統制基盤なき外部化はブラックボックスの拡大 → 可視化・統制とセットの構造転換が必要

## STEP3: 目的

- IT運用を「人に依存する固定費・リスクの塊」から「仕組みで統制された変動費・経営基盤」へ構造転換する
- 社員の時間と健康を守り、Vision2030「収益力強靭化」の成長投資へ振り向ける
- 位置づけ: 運用改善プロジェクトではなくオペレーティングモデルの転換

## STEP4: 目指す姿 — 3階層オペレーティングモデル

- デジタル戦略部（本体）＝戦略機能: IT戦略・投資判断・需要管理・ベンダ選定の最終決定・SSCへの目標設定
- SSC（子会社シェアードサービス会社）＝統制機能: SIAM運営主体としてマルチベンダ統合管理・SLA/KPI監視・コスト管理・品質検収・日常のベンダ折衝
- 外部ベンダ＝実行機能: 定常運用・保守・監視・問い合わせ対応（24/365）

SSCに統制を置く戦略的意義:
- 社員シフトの徹底（統制の実務まで本体から切り離す）
- コスト効率（軽いコスト構造、グループ内還流）
- 人材・キャリアの受け皿（運用管理人材をSSCで専門職として採用・育成）
- ナレッジのグループ内保持（ベンダ交渉力・スイッチング自由度の維持)
- 拡張性（グループ他社・海外拠点への展開でスケールメリット拡大）

## STEP5: ゴール（課題に1対1対応）

- ゴール1: 持続可能な運用体制の確立（←課題1・2）
  - 特定個人依存の業務ゼロ、24/365・新領域対応、運用人材の採用・キャリアはSSCに構築し本体の採用依存から脱却
- ゴール2: 運用コストの構造改革（←課題4）
  - TCO100%可視化 → 固定費の変動費化 → SSC主体の統合発注で総コスト◯%削減（業界相場10〜30%）
- ゴール3: 運用品質の統制力獲得（←課題4）
  - 全業務にSLA/KPI設定、インシデント・復旧時間の継続測定、監査・セキュリティ証跡の仕組み化
- ゴール4: 社員の戦力シフト（←課題3）
  - 運用従事工数◯%削減・企画業務へ再配置、過負荷とメンタルヘルスリスクの構造的解消
  - ベンダ統制機能はSSCに確立し、本体はSSCを目標管理する「賢い発注者」へ

## STEP6: 実現手段

- SSCへのベンダ統制機能移管（SIAM運営主体化）
- SIAM型統合アウトソーシング（分散ベンダの統合・責任分界の再設計）
- 標準化・ドキュメント化（移管の前提、属人化解消の実体）
- AI・自動化ツール（定型作業・問い合わせ対応の効率化）
- SLA/KPIベースの契約設計（本体-SSC間もグループ内契約で統制）

## STEP7: 進め方

- Phase 0: 可視化・アセスメント — 業務棚卸し、TCO算定、属人化リスク格付け、SSCの統制能力評価
- Phase 1: 移管・標準化 — 属人リスクの高い業務から文書化・外部移管、SSC統制体制の構築・人材確保
- Phase 2: 最適化・自動化 — SSC主体の統合発注への切替・再交渉、AI・自動化の適用
- Phase 3: 継続改善 — SLA実績によるベンダ統制、変動費コントロール、グループ展開の検討

## STEP8: 成立条件・リスク（SSC案の論点）

- 二重ブラックボックス化の回避: 本体-SSC間にもSLA/KPI・レポーティングラインを契約的に設計
- SSCの実力担保: 統制・SIAM運営能力をPhase 0でアセスメントし、不足は外部専門家登用・本体出向で補完
- 責任分界の明確化: 障害時・監査時の説明責任（本体/SSC/ベンダ）を事前定義
- 戦略機能は移管しない: IT戦略・投資判断・ベンダ選定の最終決定権は本体に残す
- コスト検証: グループ内取引価格は市場価格との定期ベンチマークで検証

## STEP9: 想定問答 — 既存社員の「今もやっている」への切り返し

基本フレーム: 反論の多くは事実として正しい。論点をずらさず「個人の努力でやれている」と「組織の仕組みとして統制できている」は別物である、に毎回収束させる。社員の努力は否定せず、「その努力に依存した構造」を課題として指摘する。

- 「ベンダ管理は今もやっている」
  → やれているのは個人の経験と関係性による管理。SLA/KPI・TCO・責任分界が文書と契約で担保されていない以上、あなたが異動した瞬間に管理は消失する。現にブラックボックス化が起きていることが「仕組みになっていない」証拠。
- 「手順書・ドキュメントはある」
  → あることと、それだけで他人が運用を引き継げることは別。第三者が手順書のみで対応できるかのテスト（引き継ぎ試験）をパスして初めて「標準化されている」と言える。
- 「品質は保てている。問題は起きていない」
  → 測定していないものは「保てている」と証明できない。かつ現在の品質は残業・手戻り対応・休日対応という見えない追加投入で成立しており、それがメンタルヘルス不調として顕在化している。問題が起きていないのではなく、人が吸収しているだけ。
- 「自分たちでやったほうが早い」
  → 短期的には事実。しかしそれこそが属人化の定義であり、「早くできる人」への集中が過負荷と不調者を生んでいる。個人の速さではなく、誰がやっても回る速さを目指す。
- 「外部化したらかえってコストが上がる」
  → 現状のTCO（社員工数・手戻り含む）が見えていないため、その比較は成立しない。まずPhase 0で可視化し、数字で比較して判断する。上がるなら外部化しない業務として残せばよい。
- 「ノウハウが社外に流出する・失われる」
  → 現状ノウハウは個人の頭の中にあり、退職で失われる状態。移管に伴う文書化はむしろノウハウを会社の資産に変える行為。統制ノウハウはSSCというグループ内に置き、戦略判断は本体に残す。
- 「SSCにベンダ統制の能力はない」
  → 正しい懸念であり、だからPhase 0で能力評価を行い、外部専門家登用・本体出向で立ち上げる計画。「今できないからやらない」なら本体の運用人材不足も同じ論理で詰む。
- 「自分の仕事がなくなるのではないか」
  → 運用の実行・調整業務はなくすが、雇用ではなく業務内容の転換。企画・データ活用・ベンダ目標管理というより市場価値の高い仕事へのシフトであり、キャリアにとってプラス。移行時の育成支援をセットで提示する。

運営上の注意:
- 説明会では「皆さんの努力を仕組みに変える取組み」と冒頭で定義し、個人批判ではないことを明確にする
- 最も強い反対者（=最も属人化を体現している社員）は、移管プロジェクトの中核メンバーに登用する（抵抗者を設計者に変える）
- 不調者・過負荷の事実は具体名を出さず構造の問題として語る

## STEP10: 定量化フレーム（前提パラメータは要差替え）

前提パラメータ（Phase 0で実数に差替え）:
- デジ戦部人員: 30名 / 平均年収800万円 / フルコスト係数1.5 → 1,200万円/FTE
- 運用従事率: 40%（業務棚卸しで検証）
- 手戻り・補完・ベンダ調整の比率: 運用工数の25%
- 外部ベンダ委託費: 年10億円（仮）
- 連結売上高: 約4,000億円 → 1日あたり約11億円

試算例:
1. 隠れ人件費 = 30名×40%×1,200万円 = 年1.4億円（12FTE）
2. うち手戻り・調整等の非付加価値工数 = 3FTE ≈ 年0.4億円
3. 真のTCO = ベンダ費10億円＋1.4億円 = 11.4億円（ベンダ費のみの管理では14%過小評価）
4. 統合発注による削減余地 = ベンダ費の10〜30% = 年1〜3億円
5. 人材投資の消失 = 採用300万円＋立ち上がり2年の非生産分600〜1,000万円 ≈ 1,500万円/名（早期離職で全額消失）
6. 休職1件のコスト = 給与保障＋代替要員＋復職支援・周辺生産性低下 ≈ 1,000〜1,500万円/件（年収の1.5〜2倍）
7. 基幹システム停止のエクスポージャ = 受発注・物流停止1日で最大約11億円の出荷リスク（実損は遅延・欠品ペナルティ・信頼毀損）
8. 戦力シフトの価値 = 12FTE（年1.4億円相当）を成長投資へ転換

ゴールKPI（定量目標の例）:
- 運用従事率: 40% → 15%以下（3年）
- TCO可視化率: 100%（Phase 0完了時）
- 運用総コスト: ▲10〜20%（3年累計で▲3〜6億円）
- 特定個人依存業務: ゼロ（引き継ぎ試験パス率100%）
- 運用起因のメンタルヘルス不調: 新規発生ゼロ
- SLA遵守率・MTTR: Phase 1でベースライン設定→毎年改善

## STEP11: 課題②の定量化 — 公開統計による裏付け

需要ドライバー別の公開データ:
- クラウド: 国内パブリッククラウド市場 2024年4.1兆円→2029年8.8兆円、CAGR16.3%・5年で約2.1倍（IDC Japan）
- SaaS/アプリ: 日本企業の業務アプリ数は平均46個で伸び率は世界トップクラス（Okta）。SaaS 11個以上の企業は前年比+5pt（メタップス）
- セキュリティ: サイバー攻撃関連通信は10年で約11倍（NICT NICTER: 2015年632億→2024年6,862億パケット）。ランサムウェア被害報告は2025年226件、アサヒGHD・アスクル等の消費財・流通大手が出荷停止（警察庁・報道）
- 生成AI: 個人利用率は1年で9.1%→26.7%と約3倍（総務省 令和7年版情報通信白書）、企業の約半数が活用方針策定済み

需給ギャップの推計ロジック:
- 市場統計から、自動化効果を差し引いても運用需要は年率7〜10%増（5年で約1.5倍）と保守的に推計
- 当社換算: 現在12FTE → 2030年18FTE相当（+6FTE・年0.7億円相当）
- 供給は採用ゼロ＋退職で減少（全国でもIT人材は2030年最大79万人不足、経産省）
- 結論: 需要は5年で約1.5倍、供給は先細り。ギャップは毎年拡大し、埋めているのは社員の残業と健康

使用上の注意:
- 「5年で1.5倍」は市場統計からの推計。脚注に「クラウド市場成長率等からの当社推計」と明記
- Phase 0でチケット数・問い合わせ件数の実測トレンドに置き換えるまでの仮説値
- 他社被害事例は「報道による」と出典を付す
