# IT運用・保守アウトソーシング検討 — 背景・課題から目的・ゴールまで（全体ストーリー最終版）

作成日: 2026-08-10
対象: ライオン株式会社 IT運用・保守アウトソーシング検討（Vision2030 2nd Stage「収益力強靭化」文脈）
特徴: 子会社シェアードサービス会社（SSC）へのベンダ統制移管を含む3階層オペレーティングモデル

---

## 全体ストーリー（1枚サマリ）

- 【背景/課題】運用の担い手は先細り（供給↓）、運用業務は増大（需要↑）、ギャップを社員の過負荷で吸収（歪み）、コスト・品質を統制する仕組みも不在（基盤欠如）
- 【So What】現状延長では社員の健康・事業継続・Vision2030の実行力が毀損。内製強化は採用面から成立せず、構造転換以外に選択肢がない
- 【目的】IT運用を「人に依存する固定費・リスク」から「仕組みで統制された変動費・経営基盤」へ転換
- 【目指す姿】本体＝戦略、SSC＝統制、外部ベンダ＝実行の3階層モデル
- 【ゴール】①持続可能な体制 ②コスト構造改革 ③品質の統制 ④社員の戦力シフト

## STEP1: 背景/課題

### 課題1【供給】運用の担い手を維持できない
- 運用・保守の専門人材を採用しておらず、人材獲得競争の激化で今後の採用も現実的でない
- 採用・育成に時間・コストを投じても、運用業務はキャリアとして定着せず投資が回収できない
- シニア社員の経験・暗黙知に依存した属人運用が存在し、異動・退職とともに運用能力が失われる
- So What: 供給は時間とともに確実に細る。「いつ外部化するか」の問題であり「するか否か」の問題ではない

### 課題2【需要】運用業務は増え続ける
- データ基盤・BI・生成AIの活用拡大により、従来と異なる新たな運用業務が増加
- セキュリティ脅威の高度化、EC・グローバル展開により24時間365日対応が標準要求に
- So What: 供給減×需要増でギャップは拡大の一途

### 課題3【歪み】ギャップを社員の過負荷で吸収している
- 定常運用・問い合わせ・障害対応など外部化可能な業務に社員が忙殺され、手戻り・補完などの隠れ工数まで負担
- メンタルヘルス不調者が発生（安全配慮義務に関わる経営リスク）
- 企画業務に時間を投じられず、Vision2030推進の機会損失が発生
- So What: しわ寄せ先は「社員の健康」と「成長投資の時間」

### 課題4【基盤】コスト・品質を統制する仕組みがない
- マルチベンダのブラックボックス化。責任分界・実工数が不明でスケールメリットも不在
- 社員工数・手戻りを含む運用総コスト（TCO）が把握できず、最適化の判断基盤がない
- SLA/KPI未整備で品質を測定できず、復旧は個人の稼働に依存。監査・セキュリティ統制の証跡も担保困難
- So What: 内製・外注いずれを選ぶにせよ、可視化と統制基盤の構築が全ての前提

## STEP2: So What（なぜ構造転換か）

- ギャップは放置すれば拡大の一途、被害はすでに顕在化
- 内製強化（採用・増員）は人材市場の構造上成立しない → 消去法でも外部活用が唯一解
- ただし統制基盤なき外部化はブラックボックスの拡大 → 可視化・統制とセットの構造転換が必要

## STEP3: 目的

- IT運用を「人に依存する固定費・リスクの塊」から「仕組みで統制された変動費・経営基盤」へ構造転換する
- 社員の時間と健康を守り、Vision2030「収益力強靭化」の成長投資へ振り向ける
- 位置づけ: 運用改善プロジェクトではなくオペレーティングモデルの転換

## STEP4: 目指す姿 — 3階層オペレーティングモデル

- デジタル戦略部（本体）＝戦略機能: IT戦略・投資判断・需要管理・ベンダ選定の最終決定・SSCへの目標設定
- SSC（子会社シェアードサービス会社）＝統制機能: SIAM運営主体としてマルチベンダ統合管理・SLA/KPI監視・コスト管理・品質検収・日常のベンダ折衝
- 外部ベンダ＝実行機能: 定常運用・保守・監視・問い合わせ対応（24/365）

SSCに統制を置く戦略的意義:
- 社員シフトの徹底（統制の実務まで本体から切り離す）
- コスト効率（軽いコスト構造、グループ内還流）
- 人材・キャリアの受け皿（運用管理人材をSSCで専門職として採用・育成）
- ナレッジのグループ内保持（ベンダ交渉力・スイッチング自由度の維持)
- 拡張性（グループ他社・海外拠点への展開でスケールメリット拡大）

## STEP5: ゴール（課題に1対1対応）

- ゴール1: 持続可能な運用体制の確立（←課題1・2）
  - 特定個人依存の業務ゼロ、24/365・新領域対応、運用人材の採用・キャリアはSSCに構築し本体の採用依存から脱却
- ゴール2: 運用コストの構造改革（←課題4）
  - TCO100%可視化 → 固定費の変動費化 → SSC主体の統合発注で総コスト◯%削減（業界相場10〜30%）
- ゴール3: 運用品質の統制力獲得（←課題4）
  - 全業務にSLA/KPI設定、インシデント・復旧時間の継続測定、監査・セキュリティ証跡の仕組み化
- ゴール4: 社員の戦力シフト（←課題3）
  - 運用従事工数◯%削減・企画業務へ再配置、過負荷とメンタルヘルスリスクの構造的解消
  - ベンダ統制機能はSSCに確立し、本体はSSCを目標管理する「賢い発注者」へ

## STEP6: 実現手段

- SSCへのベンダ統制機能移管（SIAM運営主体化）
- SIAM型統合アウトソーシング（分散ベンダの統合・責任分界の再設計）
- 標準化・ドキュメント化（移管の前提、属人化解消の実体）
- AI・自動化ツール（定型作業・問い合わせ対応の効率化）
- SLA/KPIベースの契約設計（本体-SSC間もグループ内契約で統制）

## STEP7: 進め方

- Phase 0: 可視化・アセスメント — 業務棚卸し、TCO算定、属人化リスク格付け、SSCの統制能力評価
- Phase 1: 移管・標準化 — 属人リスクの高い業務から文書化・外部移管、SSC統制体制の構築・人材確保
- Phase 2: 最適化・自動化 — SSC主体の統合発注への切替・再交渉、AI・自動化の適用
- Phase 3: 継続改善 — SLA実績によるベンダ統制、変動費コントロール、グループ展開の検討

## STEP8: 成立条件・リスク（SSC案の論点）

- 二重ブラックボックス化の回避: 本体-SSC間にもSLA/KPI・レポーティングラインを契約的に設計
- SSCの実力担保: 統制・SIAM運営能力をPhase 0でアセスメントし、不足は外部専門家登用・本体出向で補完
- 責任分界の明確化: 障害時・監査時の説明責任（本体/SSC/ベンダ）を事前定義
- 戦略機能は移管しない: IT戦略・投資判断・ベンダ選定の最終決定権は本体に残す
- コスト検証: グループ内取引価格は市場価格との定期ベンチマークで検証
